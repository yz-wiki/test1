# Internationalisation (i18n)

Skald ships English and Simplified Chinese. The runtime lives in `src/i18n/` and
is dependency-free — no i18next, no ICU bundle. Two locales do not justify a
framework; the parts that actually prevent bugs are implemented directly:

| Concern | Implementation |
|---|---|
| Key safety | `Dict = Record<TranslationKey, string>` — a locale missing a key fails `tsc` |
| Interpolation | `t('search.placeholder', { count: 42 })` → `{count}` substitution |
| Plurals | `t('toast.syncFlushed', { count })` resolves `_one` / `_other` |
| Dates & numbers | `Intl.DateTimeFormat` / `Intl.NumberFormat`, never string concatenation |
| Persistence | `skald.locale`, `skald.locale.followSystem` in localStorage |
| System sync | `navigator.language`, live `languagechange` listener when "follow system" is on |

## Using it

In a component:

```tsx
import { useI18n } from '../../i18n';

function Example() {
  const { t, formatDate } = useI18n();
  return <h1>{t('nav.home')}</h1>;
}
```

Outside React (toast builders, log helpers, error presenters):

```ts
import { t } from '../../i18n';

st.setToast({ message: t('toast.downloaded', { title }), type: 'success' });
```

`t()` reads a module-level mirror of the active locale that the provider keeps in
sync, so it is correct from the first render onward. It does **not** re-render
the caller when the language changes — for that, use `useI18n()`.

Rendering a string in a *specific* locale (used by the language preview card):

```ts
import { translateIn } from '../../i18n';
translateIn('zh-CN', 'language.previewSample');
```

## Adding a key

1. Add the key to `src/i18n/en.ts`. This file defines the canonical key set.
2. Add the same key to every other dictionary (`src/i18n/zh-CN.ts`). `tsc` will
   tell you if you forget.
3. Keep placeholders identical across locales — `src/i18n/i18n.test.ts` asserts
   this and will fail the build otherwise.
4. Use it with `t('your.new.key')`.

For plurals, add three entries: the base key (used as the fallback and for
languages with a single plural form), `_one` and `_other`.

## Adding a locale

1. Create `src/i18n/<tag>.ts` typed as `Dict`. Copy `en.ts` and translate.
2. Register it in `src/i18n/index.tsx`:
   - add the tag to `LOCALES`
   - add its entry to `LOCALE_META` (native name + region)
   - add it to `DICTS`
   - extend `normalizeLocale()` so OS tags map onto it
3. If the language needs plural categories beyond one/other (Polish, Russian,
   Arabic), extend `pluralSuffix()` with `Intl.PluralRules` — the single call site
   is already isolated for that purpose.

## Conventions

- **Keys are namespaced by surface**, not by component: `nav.*`, `search.*`,
  `settings.*`, `palette.*`, `language.*`, `toast.*`, `window.*`. A key moving
  between components should not need renaming.
- **Sentences live in the dictionary, not in JSX.** Interpolate values, never
  concatenate fragments — word order differs between English and Chinese.
- **Do not translate** identifiers, file paths, feature names ("Audiobookshelf"),
  or technical values shown for troubleshooting.
- **Keep the CJK font stack.** `--mac-font-ui` in `src/styles/macos.css` lists
  PingFang SC / Microsoft YaHei / Noto Sans SC after the Latin faces; removing
  them makes Chinese fall back to a serif on Windows.
- **CJK typography differs**: `html[data-locale='zh-CN']` loosens letter-spacing
  and line-height. Do not hardcode `letter-spacing` on translated text.

## Testing

```bash
pnpm test:front -- src/i18n
```

`src/i18n/i18n.test.ts` covers dictionary parity, empty translations,
placeholder drift between locales, plural bucket selection, locale
normalisation, and ISO/medium date formatting.
